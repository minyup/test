# 금지 규칙 스캔 (LB-134)

`SPEC.md` 4.7절 금지 규칙과 8.4절 공통 조건을 소스와 데이터 전체에 걸어 확인한 기록이다.

사람이 한 번 훑고 끝내지 않고 **테스트로 남겼다**(`issue-radar/tests/forbidden.test.ts`).
Phase 6·7에서 코드와 데이터가 늘어날 때 이 규칙이 조용히 깨지는 것을 막기 위해서다.
`npm test`를 돌릴 때마다 함께 돈다.

## 훑는 범위

`issue-radar/`의 `app/` · `lib/` · `scripts/` · `data/` 아래 `.ts` `.tsx` `.mjs` `.js` `.json` `.css`.

`tests/`는 뺐다. 스캔 테스트 자체가 금지어 목록을 글자로 들고 있어서, 스스로를 훑으면 언제나 걸린다.

| 확인 항목 | 방법 | 결과 |

| API 키 형태 문자열 | `sk-` · `ghp_` · `AKIA…` · `xox?-` · PEM 헤더 · `api_key`/`secret_key`/`access_token`/`client_secret`/`password` 대입 | 0건 |

`npm test` — 5개 파일 16개 테스트 전부 통과.

## 한 번 걸렸다가 규칙을 좁힌 것

브랜드명 스캔을 처음에는 소스까지 걸었더니 `app/globals.css`의 글꼴 스택
`'Apple SD Gothic Neo'`가 걸렸다. 금지 규칙이 막는 것은 **데이터에** 실제 브랜드명을 넣는
것이고, 코드가 시스템 글꼴 이름을 적는 것은 여기에 해당하지 않는다. 그래서 브랜드명 검사만
`data/`로 좁혔다. 키 검사와 URL 검사는 그대로 소스까지 건다.

글꼴 이름을 지우는 쪽으로 고치지 않은 이유는, 그 이름이 macOS에서 한글을 그리기 위해
필요한 값이기 때문이다. 규칙을 지키려고 화면을 망가뜨리는 것은 순서가 뒤집힌 것이다.
